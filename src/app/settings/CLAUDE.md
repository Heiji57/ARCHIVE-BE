# Settings 모듈 컨벤션

이 디렉토리(`src/app/settings/`)에서 작업할 때 적용되는 컨벤션. 루트 `CLAUDE.md`의 Key Conventions에서 이관됨.

- **국가 → tz 매핑**: ISO 3166-1 alpha-2 전 249개국 지원 (`pycountry`). 국가→IANA tz 옵션은 `pytz.country_timezones` (CLDR-derived) 사용. 단일 tz 국가(예: KR, JP, FR)는 `country` 만으로 자동 결정, 다중 tz 국가(예: US, RU, BR)는 IANA `timezone` 명시 필수. 신규 국가/tz 추가는 `pytz`/system tzdata 업데이트로 자동 반영 — 코드 수정 불필요. 국가 입력 핸들러는 `shared/domain/utils/timezone.py`의 `is_supported_country`, `country_timezone_options`, `resolve_timezone` 사용. **`region` 컬럼은 deprecated**: 신규 입력 받지 않음, 기존 DB 컬럼은 호환 위해 유지.
- **국가 변경 이력**: `user_country_history` 테이블에 (country, region, timezone, source, created_at) 기록. `source`: `registration` / `oauth_onboarding` / `settings_update`. 회원가입 시점 1행 자동 생성. `UpdateCountryUseCase` 는 실제 값이 변경된 경우에만 row 추가.
- **설정 수정은 섹션별 PATCH**: `PUT /settings`(전체 교체)는 없다 — 보내지 않은 필드가 기본값으로 덮이던 문제(GitHub push 대상이 지워짐) 때문에 섹션별 부분 수정으로 바꿨다. `general`(locale·weekStart·uiPreferences), `auto-summary`, `notifications`(보관 기간·notificationPrefs·quietHours·emailDigest), `calendar`(Google 연동), `work`(workSchedule·defaultTodoMinutes·dayEndReminder), `github`(push 대상, null=해제). 모두 `PatchSettingsUseCase` 하나를 쓰고, 요청 모델은 `model_fields_set` 으로 보낸 필드만 넘긴다(`_SettingsPatchBody.provided()`). null 을 받을 수 없는 필드의 명시적 null 은 422.
- **서버가 읽는 값 vs 화면 값**: 서버가 읽는 값은 컬럼(`week_start`, `work_schedule`, `default_todo_minutes`, `day_end_reminder`, `notification_prefs`, `quiet_hours`, `email_digest`), 값 객체는 `domain/models/preferences.py`. 요일은 FE 와 같은 0(일)~6(토)이라 파이썬 `weekday()` 와 섞지 말고 `js_weekday()` 를 쓴다. 화면에서만 쓰는 값은 `ui_preferences` JSONB — 서버는 해석하지 않고 **보낸 키만 병합, null 은 키 삭제, 모르는 키도 보존**, 8KB 상한(413 `SETTINGS_UI_PREFS_TOO_LARGE`). `defaultRetroFolderId` 가 지워진 폴더면 GET 응답에서만 null(저장값 유지).
- **주간 이메일 수신 거부**: 메일 링크 `GET /settings/email-digest/unsubscribe?token=` 는 **상태를 바꾸지 않고** FE 확인 화면(`/unsubscribe?token=`)으로 303 — 메일 스캐너가 링크를 미리 열어도 풀리지 않게. 실제 해제는 `POST` 같은 경로(인증 없음, 서명 토큰 `create_unsubscribe_token` type `email_unsubscribe` 60일, 없는 사용자면 401).
