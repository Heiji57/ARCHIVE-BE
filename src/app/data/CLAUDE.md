# data 모듈 컨벤션

이 디렉토리(`src/app/data/`)에서 작업할 때 적용되는 컨벤션. 휴지통(12 §1)과 내보내기(12 §2).

- **휴지통**: 각 모듈이 자기 테이블을 다룬다(`todo/application/use_cases/trash.py`, `retrospective/application/use_cases/entry_trash.py`) — 이 모듈은 목록 합치기와 kind 라우팅만. 목록은 30일치라 합친 뒤 메모리에서 자른다. 30일 정리는 `worker.purge_trash`(하루). soft delete 전반 규칙은 루트 `CLAUDE.md` "휴지통(soft delete)".
- **내보내기**: `POST /exports` → 202, BackgroundTasks 로 `worker.build_export` 를 넘긴다 — BackgroundTasks 는 이 스택에서 요청 커밋보다 먼저 돌 수 있어, 워커는 행이 안 보이면 1초 간격 5번 다시 시도한다. 사용자당 진행 중 하나는 부분 유니크 인덱스 `uq_exports_user_pending` 로도 막는다(동시 요청). 1시간 넘게 pending 이면 워커가 죽은 것으로 보고 새 요청 때 failed 로 닫는다. 하루 3번은 최근 24시간(롤링). 워커는 zip 을 임시 디렉토리에 다 만든 뒤 `ExportStorage`(`application/ports.py`) 로 넘긴다 — 반쯤 만든 파일이 저장소에 보이지 않게. 저장소는 비공개이고 내려받기는 24시간 서명 토큰이 붙은 `GET /exports/{id}/download` 만 — 객체 저장소면 저장소의 5분짜리 서명 URL(`attachment`)로 307, 로컬이면 API 가 바로 보낸다. 파일은 7일 뒤 `worker.purge_exports` 가 지우고 행은 남겨 GET 이 410. 빌더(`infrastructure/export/builder.py`)는 ORM 으로 읽어 휴지통이 자동으로 빠지고, `yield_per` 로 나눠 읽어 zip 에 바로 쓴다(큰 데이터에서 메모리). 계정 완전 삭제 때 파일도 지운다(`worker.purge_deleted_accounts`).
- **파일 저장소(사진·내보내기 공통)**: `STORAGE_BACKEND=local|s3`(`shared/infrastructure/config/storage.py`). `local`(기본 — 개발·테스트)은 `AVATAR_DIR`·`EXPORT_DIR` 디렉토리로, API 와 워커가 같은 디렉토리를 봐야 한다(개발 compose 의 `.:/app` bind mount). `s3` 는 S3 호환 객체 저장소(운영은 Cloudflare R2) — 버킷 둘(사진 공개·내보내기 비공개), 클라이언트는 프로세스에 하나(`shared/infrastructure/storage/s3.get_s3_client`, boto3 를 `asyncio.to_thread` 로), 라이브러리 예외는 `StorageUnavailableException`(503) 으로 바꾼다. 구현은 `make_export_storage`/`make_avatar_storage` 로만 고른다(API DI·워커 같은 팩토리). **운영(`APP_ENV=production`)은 `s3` 가 아니면 시작하지 않는다** — 운영 compose 는 컨테이너마다 볼륨이 없어 로컬 파일이면 워커가 만든 zip 을 API 가 못 보고 재배포 때 사진이 사라진다. 내보내기 버킷에는 수명 규칙(8일)을 둬 워커 정리가 빠져도 남지 않게 한다.
