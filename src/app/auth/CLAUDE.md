# Auth 모듈 컨벤션

이 디렉토리(`src/app/auth/`)에서 작업할 때 적용되는 컨벤션. 루트 `CLAUDE.md`의 Key Conventions에서 이관됨.

- **Session 보안 정책**: Refresh token = `{sessionId}.{secret}` 형식. 모든 refresh 시 rotation + reuse detection. 폐기된 RT 재등장 시 해당 사용자의 모든 세션 즉시 폐기 + `security` structlog 채널에 `session.refresh_reuse_detected` 로깅. 동시 refresh race 는 `SESSION_GRACE_WINDOW_SECONDS`(기본 5초) grace window 로 흡수 (`session.refresh_grace_hit` 로깅). 세션 정책 본체는 `auth/application/services/session_service.py`. Redis 캐시는 raw CRUD 만 담당 (`auth/infrastructure/cache/auth_token.py`).
- **운영 파라미터 (TTL/window) env 화**: 모든 시간 기반 파라미터는 `.env` 에서 관리한다. `OAUTH_STATE_TTL_SECONDS`, `ONBOARDING_TOKEN_TTL_SECONDS`, `PASSWORD_RESET_TTL_SECONDS`, `PASSWORD_RESET_COOLDOWN_TTL_SECONDS`, `SESSION_GRACE_WINDOW_SECONDS`. 기본값은 `shared/infrastructure/config/auth.py`의 `AuthConfig`. 라우터의 cookie max-age는 별도 env 가 아니라 `refresh_token_expire_days` / `onboarding_token_ttl_seconds`에서 derive — 항상 Redis TTL과 동기화 보장.
- **OAuth Link 흐름**: 로그인된 사용자의 provider 계정 link 는 `POST /auth/oauth/{provider}/link/init` (Bearer) 로 시작. 응답의 `authorizeUrl` 을 FE 가 popup 으로 직접 연다. callback URL 은 일반 로그인과 동일 — state 에 저장된 `link_user_id` 로 분기.
- **OAuth Callback URL**: dev/prod 모두 **FE proxy origin** (예: `http://localhost:5173/api/v1/auth/oauth/{provider}/callback`) 으로 통일. callback HTML 의 `window.opener.postMessage` 가 FE origin 으로 도달해야 origin 검증을 통과한다.
- **최근 로그인(`auth_time`)**: access token 에 자격 증명을 확인한 시각(epoch 초) `auth_time` 을 싣는다. 로그인·가입·OAuth·온보딩은 지금, refresh 는 세션 발급 시각(`SessionRecord.issued_at`)을 넘겨 refresh 로는 갱신되지 않게 한다. "최근 로그인" 확인(계정 삭제, 10분)은 이 값을 본다 — 토큰 발급 시각이 아니다(자동 refresh 가 15분마다 새로 발급하므로 의미가 없다). 실패는 403 `AUTH_REAUTH_REQUIRED`(401 이면 FE 자동 refresh 와 겹친다).
- **계정 삭제(soft delete)**: `DELETE /auth/me` 는 두 단계다 — 요청 트랜잭션(`DeleteAccountUseCase`)에서 `users.deleted_at` + OAuth·Google Calendar 연결 행 삭제 + 사진 키 비우기, 마무리는 작업 `worker.finish_account_deletion` 이 **`deleted_at` 커밋을 확인한 뒤**(`UserRepository.is_deleted`, 안 보이면 1초 간격 5번 다시, 끝까지 안 보이면 롤백으로 보고 아무것도 안 함) Redis 표식·세션 전부 폐기·사진 파일 삭제(`FinishAccountDeletionUseCase`)를 하고 외부 토큰 철회(`worker.revoke_account_tokens`)를 넘긴다. **이 스택(dishka 미들웨어)에서 FastAPI `BackgroundTasks` 는 요청 세션 커밋보다 먼저 돌 수 있다** — 그래서 라우터의 BackgroundTasks 는 작업을 넘기기만 하고, 커밋에 기대는 일은 작업이 확인한 뒤에 한다(Redis·파일·외부 작업을 커밋 전에 하면 롤백 때 계정은 그대로인데 로그인만 막힌다). 마무리 단계가 실패해도 refresh 가 사용자 조회로 지운 계정을 거절한다. 철회할 토큰은 Celery 인자(브로커·결과 저장소에 남음)가 아니라 1시간 TTL Redis 키(`revoke_tokens:{ref}`)로 넘긴다. 지운 계정은 soft delete 리스너로 모든 사용자 조회에서 빠져 로그인·OAuth·beat 작업 대상이 아니고, 이메일은 부분 유니크 인덱스(`uq_users_email_active`)라 다시 가입할 수 있다. 남은 access token 은 Redis `deleted_user:{id}`(access token 수명 TTL)를 `get_current_user` 가 확인해 401 — Redis 장애 시엔 통과시킨다(세션이 없어 최대 15분). 30일 뒤 `worker.purge_deleted_accounts` 가 FK 없는 사용자 테이블(`user/infrastructure/persistence/account_purge._UNLINKED` — 새로 생기면 추가)을 지우고 users 행을 지운다(나머지는 CASCADE).
- **프로필 사진**: `AvatarStorage` 포트, 구현은 로컬 디렉토리(`AVATAR_DIR`, `/static/avatars` 로 서빙) webp 256px. 키는 임의 값(사용자 id 미포함). 운영에서 객체 저장소로 옮기면 구현만 바꾼다. 바꾸거나 지운 사진의 옛 파일은 요청에서 지우지 않는다(커밋 전에 지우면 롤백 때 링크가 깨진다) — `worker.purge_deleted_accounts`(하루)가 만든 지 하루 지난, 아무도(지운 계정 포함) 가리키지 않는 파일을 지운다.
