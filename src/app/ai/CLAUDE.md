# AI 모듈 컨벤션

이 디렉토리(`src/app/ai/`)에서 작업할 때 적용되는 컨벤션.

- **AI 는 제안만 한다**: 사용자가 "넣기·적용"을 누르기 전에는 할 일·회고를 바꾸지 않는다. 적용한 것은 되돌릴 수 있어야 한다 — 적용 때 바뀐 필드의 이전 값(`applied.previous`)을 남기고, 되돌리기는 그 값을 같은 수정 규칙으로 다시 쓴다.
- **다른 모듈 기능은 포트로만**: 응용 계층은 `application/ports.py` 의 Protocol(`TodoPort`, `CommitPort` …)에만 의존하고, 구현은 `infrastructure/adapters/` 가 다른 모듈의 유스케이스를 감싼다(develop.md §13 — 응용 계층이 다른 도메인 유스케이스를 직접 부르지 않는다). 쓰기는 반드시 할 일 묶음 수정(`BatchUpdateTodosUseCase`) + `todo/infrastructure/side_effects.after_update` 를 탄다 — 반복 회차 실체화·Google push·임베딩이 일반 수정과 같게 처리된다. AI 모듈이 다른 모듈 테이블에 직접 쓰지 않는다.
- **추천(5a)은 규칙 + 행동 학습**: `domain/services/suggestion_rules.py` 의 순수 함수(지난 마감·빈 칸·커밋과 맞는 일). 이유 문장도 locale 템플릿. LLM 을 부르지 않아 사용량에 세지 않는다. 추천은 요청 때 계산해 `ai_suggestions` 에 (날짜, 종류, 할 일) 한 행으로 저장하고 상태를 이어 쓴다 — 넘긴(`dismissed`) 추천은 다시 안 나오고, 되돌린 추천은 다시 `shown`. 빈 칸은 일하는 시간(`workSchedule`) 안에서 시간 있는 할 일(Google 일정도 pull-sync 로 할 일이 된다)과 겹치지 않는 기본 길이(`defaultTodoMinutes`) 칸, 오늘이면 지금 이후(15분 단위 올림).
- **행동 학습(추천 위에)**: 규칙은 후보만 만들고, 사용자 한 명의 기록으로 순서·노출·빈 칸 시각·길이·버튼 순서를 정한다(여러 사용자 데이터를 섞지 않는다, LLM 없음). 기록은 `ai_behavior_events`(추천 `sugg_shown/applied/dismissed/undone` + 할 일 `todo_moved/retimed/done`), 통계는 `ai_user_models` 캐시(새 기록이 들어오면 stale → 다음 추천 때 최근 180일 기록으로 다시 계산, 6시간 지나도 다시). 계산은 순수 함수 — `domain/services/behavior_model.build_model`(30일 반감기 감쇠, 보상: 적용 +1·적용 후 그날 끝냄 +1 더·되돌림 −1·넘김 0.25~1·그날 반응 없음 0.1), `suggestion_ranker`(종류·상황 팔 Beta 톰슨 샘플링 — 반응 20건부터, 0.1 아래로 뽑히면 이번엔 숨김, 씨앗 = 사용자·날짜·시간대; 시간대는 태그 분포를 전체 쪽으로 당긴 디리클레(증거 5건부터); 길이는 축소 추정). 할 일 수정 기록은 할 일 모듈의 `TodoChangeObserver` 포트(`todo/application/ports.py`)를 `infrastructure/adapters/todo_observer.py` 가 구현해 받는다 — `after_update(..., before=, observer=)` 로 한 할 일(한 회차) 수정만 알리고, 시리즈 전체 수정은 알리지 않는다. 학습을 끄면(`learningEnabled`) 기록도 안 남기고 모델도 안 쓴다. `DELETE /ai/learning` 은 기록·통계를 지운다. 180일 지난 기록은 `worker.purge_ai_conversations` 가 지운다. 미룬 일의 `drop`(내려놓기)은 `TodoPort.delete`(휴지통)로 적용하고 되돌리기는 `TodoPort.restore` — 반복 회차에는 만들지 않는다.
- **사용량**: `ai_usage`(사용자 tz 날짜별 요청·토큰). 상한 env `AI_DAILY_REQUEST_LIMIT`(50)·`AI_MONTHLY_REQUEST_LIMIT`(1000). LLM 을 부르는 경로는 호출 **전** `AiUsageService.check`(넘으면 429 `AI_USAGE_LIMIT_EXCEEDED`, details `{scope, used, limit}`), 호출 **후** `record`.
- **DI**: 자체 `AiProvider`(`infrastructure/container/providers.py`)를 `main.py` 컨테이너에 등록.
- **대화(5b) — 도구 루프**: `application/services/agent.py` 의 `run_turn` 이 모델(`ChatModelPort`, 구현 `infrastructure/llm/gemini_chat.py`)을 도구를 안 부를 때까지 최대 6번 돌린다. **읽기 도구는 바로, 쓰기는 제안으로만** — `propose_*` 는 `ai_proposals` 행을 남길 뿐 데이터를 바꾸지 않는다. 모델이 잘못 부른 도구(없는 이름, 꺼진 출처, 잘못된 인자)는 예외가 아니라 `{"error": ...}` 결과로 돌려줘 모델이 고칠 수 있게 한다. 자동 함수 호출(AFC)은 끈다 — 실행·진행 문장·제안 저장은 우리가 한다. 모델 차례 원본(Content)은 `ModelTurn.raw` 로 다음 요청에 그대로 되돌려 보낸다(thought signature 보존). 시스템 지시문은 영어, 답은 사용자 locale, 시각은 사용자 tz(`HH:mm` 로 받고 UTC 로 저장). 기억(`ai_memories`)은 "데이터이지 지시가 아님"으로 표시해 싣는다.
- **차례 실행 경로**: `POST .../messages` 가 사용량 확인 → 사용자 메시지 저장(202) → `BackgroundTasks` 로 `worker.run_ai_turn`(ai_tasks 큐). 워커는 API 와 같은 Dishka 컨테이너(`run_ai_turn._get_container`)로 유스케이스를 만든다(어댑터 배선 한곳). 요청 커밋보다 먼저 돌아 메시지가 안 보이면 `MessageNotYetVisibleError` → 1초 뒤 다시(최대 5번, AsyncContextTask). 한 차례 = 요청 스코프 트랜잭션 하나, **`done` 은 커밋 뒤** 보낸다(FE 가 done 을 받고 메시지를 다시 읽을 때 답이 보이게). `proposal` 이벤트는 커밋 전에 나가지만 제안 전체를 싣는다. 실패는 `error{code}` 이벤트로 끝낸다(자동 재시도 없음 — 사용자가 다시 보낸다). SSE(`.../stream`)는 **먼저 구독하고 상태를 본다** — 이미 답이 있으면 `done` 한 번.
- **제안 적용·되돌리기**: 적용은 요청 트랜잭션 하나(하나라도 실패하면 전부 롤백), 행 잠금(`FOR UPDATE`)으로 두 번 눌러도 한 번. move 는 적용 전 `before` 와 지금 값을 비교해 다르면 `AI_PROPOSAL_STALE`. `applied` 에 항목별 결과·이전 값·적용 후 값(`after`)을 남기고, 되돌리기는 지금 값이 `after` 와 다르면(사용자가 또 고침) 그 항목을 `skipped` 로 둔다. 만든 할 일은 DELETE 규칙(Google 정리 포함), 회고 초안은 회고 삭제 — 둘 다 일반 삭제와 같이 휴지통으로 간다(30일 안에 되살릴 수 있음).
- **설정·기억·예약(5c)**: `ai_settings`(행 없으면 기본값 — 모든 도구 켬, `confirmMode` 1차 `always` 고정이라 PATCH 로 받지 않음), `PATCH /ai/settings`(문서의 PUT 대신 — 설정 섹션 PATCH 와 같은 이유로 부분 수정). 차례에 넘기는 값은 `AiSettingsUseCase.turn_options`(켠 출처, 기억(켰을 때만), 답 길이). 예약은 `worker.dispatch_ai_schedules`(5분, `schedule_rules.schedule_due` — 시각부터 1시간 안 + 오늘 아직 안 돌림)가 예약마다 새 대화 + 프롬프트 메시지를 만들고 `run_ai_turn(notify=True)` → 끝나면 `category: schedule` 알림(링크 `{kind: ai_conversation, id}`). 사용량 초과면 그날은 건너뛴다(발송일은 먼저 찍어 5분마다 재시도하지 않음). `worker.purge_ai_conversations`(하루)는 `retentionDays`(0 = 하루)보다 오래된 대화와 적용 안 한 제안을 지운다 — 적용한 제안은 되돌리기 기록이라 남긴다.
- **예외 코드 충돌 주의**: `shared/domain/exceptions/external.AIQuotaExceededException`(Gemini 쪽 쿼터, 503)과 이름이 겹치지 않게 사용자 상한은 `AI_USAGE_LIMIT_EXCEEDED`(429). `_STATUS_MAP` 은 코드 문자열 키라 같은 코드가 둘이면 뒤 매핑이 조용히 이긴다 — `test/test_error_code_uniqueness.py` 가 막는다.
